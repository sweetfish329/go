# 碁盤画像認識 (Go-WASM + OpenCV) 高度化アルゴリズム設計ガイド

本ドキュメントは、学術研究（NotebookLM/IEEE/CVPR等）および実世界の囲碁認識システム（PhotoKifu/VideoKifu, Imago, GBR, img2sgf, Kaya等）の最先端知見に基づき、`wasm-kifu`（WebAssembly / クライアントブラウザ環境）の画像認識パイプラインを劇的に高度化するための設計ガイド、アルゴリズム仕様、およびハイブリッド・パイプラインのアーキテクチャです。

## 1. 課題と先端解決アプローチの全体像

| 課題領域 | 従来の単純手法の限界 | 最先端の解決アプローチ |
| :--- | :--- | :--- |
| **格子の歪み・製造誤差** | 4隅射影変換による等間隔19等分では、数ピクセルの累積ズレが発生 | **実測間隔（Recorded Spacings）モデル** ＋ **ガウス過程回帰（GPR / SEカーネル）** |
| **格子線の重複検出・ノイズ** | 線幅や木目・文字によりハフ直線が多重検出・乱立する | **凝集型階層クラスタリング（Agglomerative Clustering / 19分割）** ＋ **KNN/K-means外れ値棄却** |
| **印刷譜面・石による格子遮蔽** | 碁石の輪郭がエッジとして誤認され、誤った格子線を検出 | **Circle-First（円形先検出）アプローチ**（石を微小ドットでマスク後に線検出） |
| **ピンボケ・密集した石の検出漏れ** | 単一平滑化では、鮮明な石とボケた石・接触した石の分離が困難 | **4層マルチスケール・ガウシアンフィルタ（並列スケール相補検出）** |
| **照明ムラ・影・木目** | 静的閾値や1D K-meansだけでは「黒石」と「木目の暗い影」の区別が困難 | **ドーナツ走査 ＋ 多次元局所特徴量 $V=[L, C, D, H]$ ＋ 動的平均石比較（Dani Ferrari手法）** |
| **反射光（グレア）・強いテカリ** | プラスチック・ガラス石の反射光で色相・輝度が白飛びする | **CCMA pix2pix（チャンネル・座標混合アテンション）** / **Swin Transformerハイライト除去** |
| **石の厚みと視差（Parallax）** | 斜めアングル撮影時に石の上面が手前にシフトし、奥の石が遮蔽される | **3Dテンプレートによる配向チャムファーマッチング（Oriented Chamfer Matching）** |
| **動画での手の通過・動体ブレ** | 毎フレーム361マス全走査は重く、誤検出率が暴落 ($0.99^{361}=2.7\%$) | **オプティカルフロー動的マスク ＋ 静止安定トリガー ＋ ミニマル差分走査** |
| **NN軽量化・端の認識低下** | 通常のゼロパディングで外周の認識精度が低下、パラメータ過多 | **ウェイト・タイイング（D4対称性束縛：重み1/8）** ＋ **エッジエンコーディング（盤外1パディング）** |
| **戦略コンテキスト・死活判断** | 白黒2値入力だけでは石の死活や手番ごとの戦況が捉えられない | **liberties（呼吸点数：1, 2, 3+）多層チャネル表現（計7〜8チャネル）** |
| **ブラウザCPUでのトランスフォーマー** | ResNetは重く、標準Transformerは解像度ダウンサンプリングで破綻 | **EfficientFormer（19×19解像度完全維持・プーリング非適用）** |
| **ルール違反の誤検知** | 誤認識で存在しない手や2手同時着手が検出される | **HMM（隠れマルコフモデル） ＋ Goルールエンジン統合（ルール違反遷移確率0）** |

## 2. 幾何学・グリッドキャリブレーションの高度化

### ① 実測間隔（Recorded Spacings）モデル
実際の碁盤は完全な幾何学的等間隔ではなく、製造誤差や経年変化、木材の収縮による歪み（長手方向比率 1.077 等）が存在します。
- **アルゴリズム**:
  1. 初期空盤キャリブレーション時に、検出された縦19本・横19本の直線間の**物理的実測ピクセル間隔 $\{d_{x, i}\}_{i=1}^{18}$, $\{d_{y, j}\}_{j=1}^{18}$** を計測・保存。
  2. 交点座標 $(u_{i,j}, v_{i,j})$ の算出時、均等内分ではなく実測間隔累積ベクトル $\sum d$ に基づいてグリッドをサンプリング。

### ② ハフ直線群の凝集型階層クラスタリング ＆ 外れ値棄却
格子線の線幅（数ピクセル）によってハフ変換で近接直線が多数検出される問題、および木目・文字ノイズを解決します。
- **凝集型階層クラスタリング（Agglomerative Hierarchical Clustering）**:
  - 縦方向・横方向それぞれの直線の切片・角度空間において、距離行列からボトムアップにクラスタリングを実行。
  - クラスタ数を正確に **19個** に強制マージし、各クラスタの重心（中央値）を最終格子線として採用。
- **KNN / K-means 外れ値除去**:
  - 格子線同士の間隔の標準偏差を計算し、極端に間隔が狭い直線（木目）や盤外の直線を統計的ユークリッド距離に基づいて事前破棄。

## 3. 前処理・画像補正の最適化

### ① 円形先検出（Circle-First）アプローチ（印刷図面・棋譜図対応）
書籍やPDFの棋譜図では、並んだ碁石の輪郭が直線として誤認識され、ハフ格子線検出を破壊します。
- **手順**:
  1. 格子線検出の前に、まず **円ハフ変換（CHT: Circular Hough Transform）** を実行して配置済みの碁石をすべて抽出。
  2. 検出された各円領域の内部を、**極小の単一ドット（中心点マーカー）または局所平均輝度で塗りつぶしてマスク**した「代替画像」を生成。
  3. 石が消去された代替画像に対して Canny エッジ検出 ＋ ハフ線変換を適用することで、遮蔽されていた格子線を100%抽出。

### ② 4層マルチスケール・ガウシアンフィルタ
- **平滑化スケール**: $\sigma \in \{1.0, 2.0, 3.5, 5.0\}$ の4層ガウシアンピラミッドを生成。
- **相補的検出**:
  - 小スケール ($\sigma=1.0$): エッジの鮮明な石を正確に検出。
  - 大スケール ($\sigma=5.0$): 照明ボケや低解像度、互いに接触して一体化した黒石クラスタの境界を滑らかにし、円形ピークを強調して抽出。

### ③ 鏡面反射（グレア）と不均一照明補正
- **CCMA (Channel-Coordinate Mixed Attention) pix2pix**:
  - チャンネル・アテンションと空間座標アテンションを組み合わせ、碁石表面の白飛びハイライトや影によるコントラスト低下をピクセル単位でクリアに再構成。

## 4. 局所色分類・特徴量抽出（ドーナツ走査 ＆ 動的平均石モデル）

### ① ドーナツ走査領域の幾何定義
- 外径 $R_{out} = \text{spacing} \times 0.35$
- 内径 $R_{in} = \text{spacing} \times 0.15$（中心の黒い格子線交差部を完全に除外）

### ② 多次元特徴量ベクトル $V = [L, C, D, H]$
1. **輝度 $L$ (Luminance)**: $L = 0.299R + 0.587G + 0.114B$ (白黒の基本指標)
2. **色度 $C$ (Chrominance)**: RGB値の標準偏差 $\sigma_{RGB}$。碁盤木目は茶・黄色で高色度、石は完全な無彩色で極低色度（影と黒石を完全に分離）。
3. **不均一性 $D$ (Disuniformity)**: 内側から外側へらせん走査した差分累積 $\sum \sqrt{(\Delta L)^2 + (\Delta C)^2}$。空の交点は木目と線で $D$ が高く、石の上は滑らかで $D$ が極めて低い。
4. **色相 $H$ (Hue) & 彩度 $S$**: 色相は影に対して不変、彩度は反射光（グレア）に頑健。

### ③ 動的「平均石（Mean Stone）」相対距離判定 (Dani Ferrari 手法)
- 時系列で確定している盤面上の石から、現在の画像における代表ベクトル $\bar{V}_{Black}$, $\bar{V}_{White}$, $\bar{V}_{Empty}$ を動的算出。
- 判定基準:
  - 基準 (a): $\text{Dist}(V, \bar{V}_{Stone}) \le \frac{2}{3} \text{Dist}(V, \bar{V}_{Empty})$
  - 基準 (b): 当該交点と平均石の距離が、全交点を距離順ソートした後続15交点の平均距離の $\frac{2}{3}$ 以下（突出性）
  - 基準 (c): 離散導関数（変化率）が後続15交点の平均変化率の 6倍以上（孤立ピーク）

## 5. 斜め（俯瞰）アングルでの3次元的視差とオクルージョン対策

### ① 配向チャムファーマッチング（Oriented Chamfer Matching）
- **課題**: カメラが斜め（30°〜60°俯瞰）の場合、碁石の厚みによって上面中心が手前にずれて投影され（Parallax）、奥の石が手前の石を部分遮蔽する。
- **対策**:
  - 事前に楕円・円錐台の3D碁石幾何テンプレートを作成。
  - エッジ方向（Gradient Orientation）を考慮した配向チャムファー距離（Oriented Chamfer Distance）により、テンプレートと実画像の距離場をマッチング。
  - 重いニューラルネットを使わずに、低解像度・部分遮蔽下でもピクセル平面上の石の実際の設置交点を高精度に算出。

## 6. ニューラルネットワーク・DCNN設計の囲碁ドメイン最適化

もし将来的に ONNX ランタイムを Go-WASM / WebGL 上で稼働させる場合、以下の囲碁ドメイン特化アーキテクチャを採用することで、モデルサイズを極限まで軽量化しつつ精度を最大化します。

### ① ウェイト・タイイング（Weight Tying / D4対称性束縛）
- **理論**: 碁盤は $90^\circ, 180^\circ, 270^\circ$ の回転、および水平・垂直・対角反転（Dihedral Group $D_4$）に対して不変。
- **実装**: 畳み込みカーネルの重みを8方向の対称性で共有・束縛（Weight Tying）。
- **効果**: **パラメータ数を約1/8に削減**しながら、**予測精度が約2%向上**し、過学習を防止。

### ② エッジエンコーディング（Edge Encoding）チャネル
- **課題**: 通常のゼロパディングを行うと、CNNフィルタが「盤外領域」と「盤内の空交点」を区別できず、外周（1の線・星・隅）の認識精度が落ちる。
- **対策**: 入力テンソルに「盤内=0、盤外パディング=1」を示す専用のエッジエンコーディングチャネルを追加。外周境界の明示的認識を可能にする。

### ③ liberties（呼吸点数）多層チャネル表現
- **テンソル構成（計7〜8チャネル）**:
  - チャネル 1〜3: 現在の手番プレイヤーの石（呼吸点が 1, 2, 3以上）
  - チャネル 4〜6: 相手プレイヤーの石（呼吸点が 1, 2, 3以上）
  - チャネル 7: シンプルコウ（着手禁止交点）
  - チャネル 8: エッジエンコーディング

### ④ EfficientFormer（19×19解像度維持トランスフォーマー）
- 一般のVision Transformerと異なり、Patch Embeddingやダウンサンプリングを行わず、**入力から出力まで $19 \times 19$ の空間次元を 100% 維持**。
- Wasm / WebWorker 上で 10ms 以下の超低遅延推論を実現。
